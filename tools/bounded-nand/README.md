# Bounded physical NAND reads (developer preparation)

This is a source-owned **read-only** primitive for the native SNES installation investigation. It is not installed, bundled in the app, or exposed through public installation controls. A separate developer-only read-only capture can upload it to private recovery RAM. It cannot erase or write NAND. No firmware eligibility is produced.

The shared walker permits only aligned 128 KiB units inside the fixed physical interval `[0x600000, 0xd00000)`. It checks the entire request using subtraction before addition, verifies geometry without overflowing, and repeats the bound immediately before each read. Every ioctl uses raw mode 1. A bad block or any I/O/output error stops the sequence; it never relocates/retries that unit or emits its rejected bytes. Previous accepted output can already exist when it fails, so callers must require a successful exit and exact output size, not treat stdout as completion.

`main.c` is freestanding little-endian 32-bit ARM Linux EABI. Its only device operations are a geometry test and physical read ioctl on the fixed `/dev/nanda` path, opened read-only with no symlink following. Command syntax is `read-active <unit-count>` with 1–56 units, or `geometry` to emit exactly the checked 24-byte geometry record without reading any NAND unit. It reads from physical unit48 through at most103. Geometry must describe power-of-two pages/blocks totaling exactly128KiB per block, with enough physical blocks to cover the exclusive bound. The original source's logical `read_boot2` format/hash behavior is not reproduced: this primitive emits physical units, not a validated Android boot image.

## Source correspondence boundary

ABI corroboration is the previously retained primary source in `NES/work/verification/stock-kernel-restore-2026-10-18`: upstream-sntool.c (source commit fd525ac710988d12fb9e37213b5fc75651ba47c0) and upstream-nand_blk.c. Its packed 32-bit burn parameter is28bytes and geometry record24bytes. `_IO('v',121)` is0x7679 (geometry test) and `_IO('v',124)` is0x767c (physical read). The source resets flags and reports badblocks; raw1 stops at the requested physical unit instead of logically retrying the data on another block. The retained source is interface corroboration. The later focused binary audit below establishes specific branch and output-flag facts; actual device geometry remains unverified for this new helper.

The old pinned dirty sntool executable is **not** reused. No write ioctl, high-level burn wrapper, bootloader operation, partition operation or automatic bad-block retry is included. A future writer needs its own complete source/binary/driver audit, exact backup/preimage and journal, a bounded write/erase strategy, and reviewed physical tests. Do not infer a safe writer from these read tests.

## Verification

### Runnable ARM integration checks (October 22)

`scripts/build-bounded-nand.sh /absolute/existing/output /absolute/path/to/zig` links a self-contained ARM EABI5 read-only ELF with the privately verified Zig0.17.0 toolchain. It records source hashes and keeps `firmwareEligible` and `hardwareTested` false. No global compiler install or runtime app dependency is needed.

Compile the test-only tracer with the same Zig using `cc -target arm-linux-musleabi -mcpu=cortex_a7 -O2 -UNDEBUG -static -std=c11 -Wall -Wextra -Werror tools/bounded-nand/test_linux_arm.c -o /absolute/test-linux-arm`. `-UNDEBUG` is required: disabled assertions refuse compilation. Never include this tracer in a recovery image.

Run `python3 tools/bounded-nand/test_arm.py --kernel /absolute/generic-kernel --busybox /absolute/static-busybox --helper /absolute/bounded-nand-read --tracer /absolute/test-linux-arm --qemu /absolute/qemu-system-arm --output /absolute/test-output`. The kernel and BusyBox digest checks select the reviewed generic test inputs. The isolated VM has no console USB, network, disks or host shares. Synthetic ioctl interception exercises the actual linked helper, including full-range output, invalid arguments before open, wrong geometry/magic, damaged blocks, changed replies, known/unknown status flags and failed stdout. Its synthetic `/dev/nanda` stays unchanged. All 20 isolated ARM cases passed for the 11,928-byte geometry-capable helper SHA256 `59dc6f084106cb4d08b56d9bbb6abcd9a1f9f09de3c668018432eabdb9066ae0`. These tests establish syscall/ABI handling, not hardware validation.

The pinned recovery driver has now been inspected as inert ELF bytes. See `docs/SNES-PHYSICAL-IO-AUDIT-2026-10-22.md` and `audit_pinned_driver.py`. Unlike the older retained source, its read path sets output bit0 when spare-area byte1 is nonzero. The helper permits only that known bit and still rejects unknown bits and any bad-block count. Caller transport must separately bind the pinned module, console identity and complete output to a successful result. This audit covers the indicated branch sites; it is not a whole-driver proof or installation authorization.
