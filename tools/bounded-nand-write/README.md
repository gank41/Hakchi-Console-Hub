# Bounded SNES active-startup writer (developer implementation)

This is a separate source-owned tool, not the read-only reader and not a public installation control. No hardware test or firmware authority is implied by its build or synthetic checks.

`verify-active PREIMAGE_SHA TARGET_SHA GEOMETRY_SHA UUID` and `replace-active ...` accept exactly 24 geometry bytes + 7,340,032 preimage bytes + 7,340,032 target bytes on stdin, followed by EOF. Vendored Mbed TLS SHA256 checks all three caller-reviewed digests before the fixed `/dev/nanda` node is opened. No input path, offset or slot is accepted. The entire input is retained in process RAM; no mutable file chunk is consumed during mutation.

The node opens read-only for verify or read-write for replace, with NOFOLLOW/NONBLOCK. `fstat` requires a block device. The original kernel's legacy stat ABI is supported through static musl's statx-ENOSYS fallback. The checked geometry must exactly equal the reviewed record, have valid 128KiB units and cover the exclusive bound. Flush support is checked before any write.

Only `[0x600000,0xd00000)` is accessible, as 56 fixed physical128KiB units. All56 units must match the complete preimage before any write. Verify mode then exits without write ioctls. Replace mode skips equal units, rechecks each changed unit immediately before writing once with raw1/count1, flushes, and compares immediate readback. A final comparison includes all untouched trailing units. Driver ioctl0x767d performs its own per-unit erase/program; there is no logical burn wrapper, relocation, NAND retry, separate erase ioctl, bootloader/partition operation, reboot or reset. Read/write request pointers, lengths, offsets, OOB and output flags are checked; only known tag bit0 is accepted, badblocks always fail. The focused pinned-driver audit is in docs/SNES-PHYSICAL-IO-AUDIT-2026-10-22.md.

Every nonzero result is failure. After a host write intent, even a lost response or interrupted output is uncertain: never infer success, retry or reboot automatically. The host must retain its durable intent, perform independent complete readback, and obtain human normal-boot/gameplay confirmation. Positive stdout contains only the mode-specific completion marker, exact caller UUID and target digest. A successful preflight marker is never a write result.

`check.sh` runs the real core against synthetic memory under AddressSanitizer/UndefinedBehaviorSanitizer (fatal sanitizer errors) and compiles it for ARM. `scripts/build-bounded-nand-writer.sh OUTPUT ZIG` links static Linux ARM EABI5 with privately verified Zig0.17.0, records source hashes and leaves firmwareEligible/hardwareTested false.

Build `test_linux_arm.c` with the same Zig, ARM target, `-static -O2 -UNDEBUG -std=c11 -Wall -Wextra -Werror`. The separate test tracer is never installed. `test_arm.py` uses the reviewed generic kernel/BusyBox and an isolated VM with no console USB, network, host share or disk. It executes the actual helper while intercepting all NAND ioctls; simulated writes affect only the tracer's RAM. Thirty-one cases cover full preflight/replacement, last-unit mismatch before first write, immediate recheck change, malformed complete input, wrong geometry/node, unsupported flush, read/write errors, badblocks, known/unknown flags, reply mutation and readback mismatch. The synthetic backing node stays unchanged. These checks prove the indicated process/ABI behavior, not safety on untested hardware.

An optional `--upload-command` runs five no-clobber upload cases through that actual ARM BusyBox shell, including existing regular files, symlinks and dangling symlinks. Only synthetic RAM paths are used.
