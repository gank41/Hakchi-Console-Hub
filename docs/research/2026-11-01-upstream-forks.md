# Upstream forks review

Reviewed on November 1, 2026. The [upstream Swift Hakchi2 repository](https://github.com/mattackerman808/swift-hakchi2) has four public forks, including this project. Commit counts are relative to upstream main at the time of review and will change.

- [coloboxp/swift-hakchi2](https://github.com/coloboxp/swift-hakchi2): 27 commits ahead. Its [recovery service](https://github.com/coloboxp/swift-hakchi2/blob/main/SwiftHakchi/Services/RecoveryService.swift) includes Mega Drive partition handling and NAND/eMMC backup paths. Its [port status](https://github.com/coloboxp/swift-hakchi2/blob/main/docs/PORT_STATUS.md) reports SNES hardware work; it does not establish Genesis hardware validation.
- [jefferysgoffnatur/swift-hakchi2](https://github.com/jefferysgoffnatur/swift-hakchi2): six commits ahead. The author's [upstream pull request](https://github.com/mattackerman808/swift-hakchi2/pull/1) describes fixes for SNES transfer stalls, menu parsing and SFROM conversion, along with the author's testing. Its stated hardware results do not by themselves validate this project or every console.
- [andrewyoo/swift-hakchi2](https://github.com/andrewyoo/swift-hakchi2): no commits ahead of upstream main at review time.

These projects provide useful implementation references, especially for Genesis backup. Their code has not been imported by this review. Check behavior, provenance and applicable licenses before reuse; a repository's visibility or a fork count alone is not evidence of a project-wide license.

## Broader all-in-one opportunities

The Coloboxp [port status](https://github.com/coloboxp/swift-hakchi2/blob/main/docs/PORT_STATUS.md) lists additional reference points: per-game emulator/core selection, other game-system formats, multi-file CD imports, incremental synchronization and console import, save-state import/export, screenshots, module repositories, controller options and folder trees. Its [system catalog](https://github.com/coloboxp/swift-hakchi2/blob/main/SwiftHakchi/Models/SystemCatalog.swift), [menu tree](https://github.com/coloboxp/swift-hakchi2/blob/main/SwiftHakchi/Models/MenuTree.swift), and [console tools](https://github.com/coloboxp/swift-hakchi2/blob/main/SwiftHakchi/Services/ConsoleToolsService.swift) show specific design choices to compare. Its stated hardware coverage is narrower than its feature list; in particular, the review found no Genesis hardware-test claim.

Our app already has staged NES/SNES menu and sync work and a legacy Clovershell connection path. Compare behavior before replacing those paths; Coloboxp describes Clovershell as outside its current transport support. The [Hakchi2 CE project](https://github.com/TeamShinkansen/Hakchi2-CE) remains an upstream reference for console tooling. Optional emulators or modules should be presented as additional components with their own compatibility, recovery and licensing requirements, rather than as automatic support for every game.

## Project ancestry and additional macOS reference

GitHub identifies this repository as a fork of [Swift Hakchi2](https://github.com/mattackerman808/swift-hakchi2), which is a separate repository rather than a GitHub fork of [ClusterM's original Hakchi2](https://github.com/ClusterM/hakchi2). [Hakchi2 CE](https://github.com/TeamShinkansen/Hakchi2-CE) is a GitHub fork of ClusterM's project. Both the original and CE report GPL-3.0; Swift Hakchi2 and the Coloboxp fork do not provide a project-level license. The upstream [SNES fixes pull request](https://github.com/mattackerman808/swift-hakchi2/pull/1) also identifies CE-derived GPL code and flags licensing for review. A GitHub fork relationship or a public repository alone does not establish a license for copying their contents into this project.

[Hakchi3 for macOS](https://github.com/paxpuig/Hakchi3-port-OSX/tree/8f49bfac1fbe2b0909142456ad19be3d688dffdb) is a separate GPL-3.0 macOS port of CE. The author reports a successful game transfer on an already-modified PAL SNES and explicitly says first-time installation has not been tested end to end on factory hardware. Its [FEL and install code](https://github.com/paxpuig/Hakchi3-port-OSX/tree/8f49bfac1fbe2b0909142456ad19be3d688dffdb/macos/Hakchi.Core/Install) is useful for comparing device handling, backup and user guidance. Do not infer Genesis or stock-console support from those results.

## Comparison with Console Hub

The SNES pull request describes stalled SSH uploads when the peer's receive window fills. Console Hub's RNDIS bridge uses a placeholder socket, and its upload writer also uses blocking mode. A local experiment reproduced the reported timeout and explored retries. Review found that a partially sent packet can leave libssh2 unable to send EOF or safely free the session, and that the USB send can outlast the apparent deadline. The experiment is not enabled in the app; safe session abort and real-transport tests are required before adopting a fix. The replay did not establish TCP retransmission behavior or on-console reliability.

The same pull request describes the apostrophe-plus-digit SNES menu error. Console Hub already substitutes a typographic apostrophe at the console-export boundary, preserving local names; `SNESCloverMenuTextTests` covers this behavior. Its selected menu layout also writes explicit sort ranks. These features should be compared and tested, not replaced wholesale.

For Genesis, the Coloboxp recovery service offers examples of partition detection and NAND/eMMC reads, but the stated tests do not establish Genesis hardware behavior. Before integrating a backup workflow, independently verify the target model, device layout, image size, read-only transport, backup verification and recovery path; review the project's missing license and third-party obligations before copying implementation code. No console flashing or Genesis sync is enabled by this research.
